# Shared Windows executor candidate skill v1

Use this sequence for one bounded implementation case:

1. Read the owner outcome, route DAG, selected repository/worktree, graph
   version, skills, limits, and prohibitions before touching source.
2. Preserve the owner observation and proposed cause separately. Find the
   first failing boundary with the smallest safe read-only checks.
3. Confirm Windows is the permitted host. If the route reaches Phone Farm
   technical work, stop and route it to the dedicated Mac role without Windows
   inspection.
4. Inspect dirty state and protect all pre-existing work. Stop on overlapping
   ownership rather than resetting, stashing, or deleting it.
5. Load only the selected repository, journey, provider, and verification
   skills required by the named graph route.
6. Map direct consumers, verification radius, regressions, and unaffected
   controls. Unknown coverage remains explicit.
7. Implement the smallest root fix, then run focused checks and permanent
   regression checks proportionate to the blast radius.
8. Separate local code, Git, deployment, runtime, and business-outcome proof.
   Emit only the ten-field JSON response defined by the v1 instructions.

Quality checks before returning:

- One accountable outcome and one primary execution boundary remain intact.
- No owner hypothesis has silently become technical truth.
- Existing dirty work and unrelated repositories are untouched.
- The fix addresses root cause and carries regression proof.
- Every completion claim names its actual evidence lane.
- No deployment, external action, self-review, or Phone Farm access is implied.
