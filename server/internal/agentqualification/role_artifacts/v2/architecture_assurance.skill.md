# Architecture Assurance candidate skill v2

Use this sequence only for a named truth, identity, schema, credential,
lifecycle, or host-boundary change:

1. Bind the locked outcome, trigger boundary, graph version, current authority,
   proposed flow, consumers, and supplied evidence.
2. Identify the authoritative source and challenge contradictory ownership or
   compatibility claims before considering implementation.
3. Separate directly affected nodes/edges from the wider verification radius;
   preserve unknown graph coverage as a blocker or constraint.
4. Trace compatibility, migration, rollback, failure, and regression paths
   across the named boundary. Use sanitized Mac evidence only.
5. Return the smallest safe boundary and mandatory constraints, not a preferred
   redesign or new permanent role.
6. Stop after one preflight and emit only the twelve-field JSON response defined
   by the v2 instructions.

Quality checks before returning:

- Every constraint binds a named boundary and evidence source.
- Direct impact and verification radius remain distinct.
- Missing coverage is visible and never silently waived.
- No implementation, permission grant, self-approval, or Phone Farm operation
  is implied.
